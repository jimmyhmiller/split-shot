Here the thing being specialized is itself a partial evaluator: jsmix, written in the same JavaScript subset. The Rust evaluator specializes jsmix to the interpreter below, leaving the source program dynamic. What comes out reads a source program and emits compiled code for it: a compiler. Nobody wrote its code generator. jsmix's only rule is that an operator with a dynamic operand is emitted as that same operator, so the +, * and - in the output come straight from the interpreter.

The Futamura projections

A partial evaluator, mix, takes a program and the part of its input that is already known, and produces a specialized program that only needs the rest. In 1971 Yoshihiko Futamura noticed three consequences:

  1. First projection. mix(interpreter, source) = target. Specializing an interpreter to a source program compiles that program.
  2. Second projection. mix(mix, interpreter) = compiler. Specializing the partial evaluator to an interpreter produces a compiler.
  3. Third projection. mix(mix, mix) = compiler generator. Specializing the partial evaluator to itself produces a program that turns interpreters into compilers.

This partial evaluator

The engine is a generic online partial evaluator written in Rust. It symbolically executes the program, keeping values static when it can, and emits residual code for the rest. Each residual block is memoized on its abstract state, which is how loops whose iteration count depends on the dynamic input tie back into residual loops. A whistle (a growth check) decides when to give up on unrolling and generalize instead. Language-specific behavior sits behind a small client trait. The JavaScript client parses real JS with SWC and models the heap, closures, exceptions and JS's coercion rules.

Everything on this page runs in your browser. The Rust engine is compiled to WebAssembly and runs in a Web Worker. Specializations that run away are cut off by the engine's weight budget or by a timeout.

jsmix2, the self-applicable one

The third projection needs a partial evaluator that can specialize itself, so it has to be written in the language it accepts. jsmix2 is about 500 lines of a small pure JavaScript subset. Two design choices make self-application produce real compilers rather than interpreters in disguise. Values carry explicit binding-time tags, and arrays can be partially static (a known length with each element tagged separately), so when jsmix2 specializes itself, the inner copy's tags stay known even though its data doesn't. Calls under a dynamic condition become residual functions memoized on the static parts of their arguments, so loops in the subject program become recursive functions in the output.

Limits

  • The entry point is main(x) with one dynamic argument.
  • It handles a subset of JavaScript. Unsupported constructs are reported as errors.
  • Recursion whose depth depends on dynamic data is out of scope for the JS client, and so is folding some static arithmetic, such as % and /.
