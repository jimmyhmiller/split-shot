Interpretation and limits:
8/10 standalone chunks emit residual JS, at 1.74–3.91 times the input size.
Input is minified production code; output is formatted, so raw size growth is
not an instruction-count or runtime-performance measurement.
Standalone main is an identity entry, added to let the CLI process script-load
effects. The registration tests check module IDs, nested registration structure,
factory presence, and early errors with and without a document object. Factory
bodies are not comprehensively exercised. Neither complete Next.js hydration nor
browser performance is tested. Turbopack runtime execution reaches matching early
ReferenceErrors in the deliberately limited VM environment.

Selected-module cases retain the whole unmodified 32,326-byte downloaded chunk
inside main. A local registration queue and fixed factory index select the real
411752 interop helper or 432979 HTTP status helper. These factories require no
imports, so no fabricated require implementation or extracted factory is used.
The small residuals require an explicit synthetic Error constructor with no stack;
this disables the chunk's debug-ID path in this controlled host environment.
The native Error comparison is retained: 75,804/75,837 bytes instead of 68/165.
That comparison shows a precision barrier; it does not establish its internal
root cause. Tiny residuals are not a claim that the full application shrank.
Both configurations pass 18 interop / 16 status calls against their original
wrappers. Interop tests include ES-module and ordinary-object inputs; status
checks include a string '404' which must not match numeric 404.

Blockers:
- 1qbb90gh_01zx: assignment to named function expression is rejected.
- 3njl687qe8dmd: 2M budget exceeded; a separate 20M attempt was terminated
  after 30 seconds. Merely raising the budget did not give a quick result.
- caught-invalid-constructor.js: Node returns 7, evaluator panics rather than
  handling the thrown TypeError. Logged in split-shot-bugs with reproducer.

Next useful work: investigate why native Error/debug instrumentation loses
precision, fix catchable invalid-constructor handling, support named function
self-assignment, and then select dependency-bearing modules through the actual
Turbopack runtime before attempting full application specialization.
