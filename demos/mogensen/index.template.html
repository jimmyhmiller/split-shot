The whole specialization idea.

P(Var x)       = x
P(SApp f x)    = P(f)(P(x))
P(SLam body)   = x ⇒ P(body(x))
P(DApp f x)    = App(P(f), P(x))
P(DLam body)   = Lam(x ⇒ P(body(Var(x))))

S executes now. D builds code for later. Syntax is encoded as functions; represented binders use actual binders. That is what makes this kernel so small.

Self-application you can inspect.

The first projection runs these rules on an annotated interpreter. The second runs them on the specializer’s own annotated lambda term, Pᵃ. The third supplies Pᵃ as both the program and its static input.

The resulting compiler and generator are ordinary lambda terms. A generic lambda evaluator executes them; they never call back into the host specializer.

This is the annotated kernel, with the paper’s manual annotations. The parser, runtime, readback, and interface are additional machinery. This demo uses the call-by-value fixed point Z in place of Y to run in JavaScript.
